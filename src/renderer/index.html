Display

The window this game runs in, written straight into its OptiScaler.ini. It applies the next time the game starts. The in-game panel saves the whole file whenever you change something in it, so if you have it open, close it before changing anything here.

This game runs the 32-bit route, so these are read from and written to host64\OptiScaler.ini -- the copy the helper process actually loads.

An emulator hands DLSS 5 its whole window, so the model works at your display resolution whatever internal resolution is set in the emulator -- at 4K that is four times the work of 1080p. Pick the resolution the model should work at instead; the picture stays at display size and only the model's own work is done smaller and enlarged. Match it to the emulator's internal resolution for the best cost/quality. The same value is the Model resolution slider in the in-game panel (Alt+Shift+Home).

Neural pass

Overrides the build chosen in Settings, for this game only. The Pre-SR Multipass fork can run Neural Rendering before DLSS upscaling, which is faster at the same output resolution, but it draws no panel inside the game: Alt+Home does nothing on it, and the pop-out panel (Alt+Shift+Home) is the way to change these settings while the game runs. Takes effect when you press Install on this game.

A DirectX 8/9 game needs a layer in front of it before DLSS 5 can reach it: dgVoodoo2 turns it into Direct3D 11, DXVK turns it into Vulkan. A 32-bit DirectX 10/11 game runs natively by default, and DXVK can run it on Vulkan instead. Neither is better everywhere -- some games only draw under one of them (Assassin's Creed II shows a black screen under dgVoodoo2 and runs under DXVK). On a 32-bit game, DXVK also needs ReShade's 32-bit Vulkan layer, which asks for administrator permission and is installed for the whole PC.

This game has no DLSS of its own -- Luma Framework's Unreal Engine mod replaces its stock TAA with DLAA, which is what gives OptiScaler's Neural Rendering pass a real DLSS call to hook. Untested by this app against a real install -- built from Luma's actual release files and the OptiScaler wiki's setup page for this game, not guessed, but never run against the game.

Frame Generation

The game's own frame gen, not OptiScaler's -- this only versions the DLL it already loads (nvngx_dlssg.dll).

The game's own DLSS Frame Generation -- how many frames it makes per rendered frame. Turn Frame Generation on in the game's video settings as usual; this only changes the multiplier it asks for. 3x and 4x need an RTX 50 series -- other cards stay at 2x. Also adjustable live from the Alt+Home panel.

RTXMFG by dashdogy unlocks 3x, 4x (up to 6x) and Dynamic Frame Generation on RTX 40 cards, and experimentally on RTX 30, in games that already have DLSS Frame Generation. It is a separate, experimental mod: fetched from its GitHub release and checked against its published checksums, then placed beside the game exe under a DLL name the game loads. It works with or without OptiScaler. In the game, turn Frame Generation on and press Backspace for its menu. Artifacts, freezes or black screens are possible -- Remove takes it out again. Only reachable on a D3D12 game with no frame gen of its own -- OptiScaler's own FG needs the game's swapchain to be D3D12, no way around that. AMD's own tech (FSR3), not NVIDIA's -- doesn't need Streamline. Estimated motion vectors, same as Neural Rendering here, so expect more artifacting than a native DLSS-G game.

More FPS for this game: Lossless Scaling adds generated frames. Set the game to Borderless or Windowed in its own display settings: Lossless Scaling cannot capture exclusive fullscreen.

Lossless Scaling generates extra frames from outside the game entirely -- it never touches the game's swapchain, so it works for games that have no DLSS of their own -- DX11 titles, DLSS5 Feeder and Luma UE games -- where neither the game nor OptiScaler's own Frame Generation can run. It is not offered for games with native DLSS: those have NVIDIA's own Frame Generation in their video settings (versioned above). Separate paid app; this only configures its per-game profile (Frame Generation on, Scaling off), it doesn't install it. Fixed multiplies every frame; Adaptive generates only as many frames as needed to hold the target FPS you set. One frame generator at a time: configuring this turns OptiScaler's own Frame Generation off for this game, and the game's own DLSS Frame Generation must be off in its video settings while Lossless Scaling runs -- two generators stack their frames. Once configured, the on/off toggle (and the amount, in Fixed mode) live in this game's own in-game panel (DLSS 5 Neural Rendering, Alt+Home) and are driven through Lossless Scaling's own hotkey, so its window never appears over your game. Configuring here also sets Lossless Scaling to start minimized to the tray and not as administrator -- that is what keeps it out of sight and lets the in-game controls reach it. Requires this game running Borderless or Windowed, not exclusive Fullscreen -- Lossless Scaling cannot capture an exclusive-fullscreen window at all; a DX12 game is usually fine regardless since DX12 has no true exclusive fullscreen.

Advanced

Some games ship more than one renderer -- Where Winds Meet links DX11 in its exe and carries a DX12 path beside it -- and detection can only name one. The upscaler key, the DLSS5 Feeder, OptiScaler's own Frame Generation and DLSS NR on AMD all follow this, so pick what the game's own video settings actually use. Applied to OptiScaler.ini straight away if it is installed.

This game has no native DLSS, so there's no DLSS call for OptiScaler to add Neural Rendering to. The Feeder synthesises one from ReShade's own depth and motion vectors -- estimated, so it ghosts more in fast motion than a native-DLSS-fed game. Deploys ReShade (as a plain ReShade64.dll, not a proxy), the Feeder add-on, and a motion-vector shader here; install OptiScaler normally afterward (Install button) -- it loads ReShade itself once installed, not the other way round.

The DLSS5 Feeder estimates motion with a ReShade shader beside the game. If the picture jumps or smears when things move, try another one: LumeniteFX is the one the Feeder recommends (its licence is shown before anything is fetched); VORT is the default; iMMERSE only when your own copy is already in the game folder. Applying swaps the shader files and the preset only -- nothing else is reinstalled.

Installing Luma UE for STAR WARS Jedi: Fallen Order

Deploying the files is only half of this -- the DLSS call OptiScaler needs won't exist until you also turn DLSS on inside Luma's own overlay, in-game. Follow all of these steps in order.

  1. Check the licence checkbox below, in the Luma UE section of this Edit Game screen. Luma Framework's licence needs your explicit confirmation before this app will fetch anything on your behalf -- it always downloads live from the official GitHub release, never a bundled copy.
  2. Click "Deploy Luma UE". This downloads and places everything Luma needs directly in the game's folder: its shader files, its own dxgi.dll renamed to ReShade64.dll, its compiled add-on, and nvngx_dlss.dll. OptiScaler itself must already be installed for this game first (use the Install button) -- Deploy only adds Luma on top of that.
  3. On AMD or Intel graphics, also check the workaround checkbox beneath Deploy (applies Spoofing.Dxgi=false and Dx11withDx12.DontUseNTShared=true to OptiScaler.ini, per the OptiScaler wiki's own setup page for this game). Skip it on NVIDIA.
  4. Launch the game normally (through this app or Steam) and get into actual gameplay, not just a menu or loading screen.
  5. Press the Home key in-game. This opens Luma's own overlay -- it is separate from OptiScaler's menu (Alt+Home) and won't appear unless deploy actually succeeded.
  6. Select DLSS as the upscaling method inside Luma's overlay. This is the step that actually matters: until DLSS is chosen here, the game keeps using its own stock TAA, no DLSS call ever happens, and OptiScaler's Neural Rendering panel will keep saying "waiting for the upscaler to run" indefinitely -- correctly, because nothing is running for it to hook yet.
  7. Open OptiScaler's own menu (Alt+Home) and check the DLSS 5 Neural Rendering panel to confirm it's picked up a real evaluate call.

Known open upstream issue (Luma-Framework #122, unresolved): opening any in-game menu after this can cause brief character pop-in and visible noise. That's a Luma bug, not something wrong with your setup.

One more file for Resident Evil

Resident Evil 2, 3, 4, 7 and Village have no DLSS of their own. REFramework makes the DLSS call instead, through PureDark's free Upscaler Base Plugin (PDPerfPlugin.dll). It is PureDark's work and only available from Nexus Mods, so this app cannot download it for you -- but you only get it once: this app then puts it in every one of these games, now and when you install more.

  1. Open the Nexus Mods page and download the main file (a free Nexus account is needed).
  2. Come back here. The download is found in your Downloads folder -- press Use this file. If you saved it somewhere else, press Browse.
